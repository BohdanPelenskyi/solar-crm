# Solar CRM — повний опис та аудит процесів

Дата перевірки: 2026-10-12. Гілка `master`, коміт `19c70f3`.

## 1. Що це

Внутрішня CRM для компанії, що монтує сонячні електростанції. Один проєкт = один клієнт/об'єкт. До проєкту прив'язані контакти, фінанси, документи, фото/відео, завдання та обладнання.

## 2. Стек і структура

| Шар | Технології |
|---|---|
| API (`apps/api`) | NestJS 11, Prisma 7 (adapter-pg), PostgreSQL, JWT (`@nestjs/jwt`), bcryptjs, multer, class-validator |
| Web (`apps/web`) | React 19, React Router 8, Vite 8, Tailwind 4, lucide-react, TypeScript 6 |
| Резервне копіювання | `scripts/backup-crm.ps1` (PowerShell + pg_dump) |

```
solar-crm/
├─ apps/api/        NestJS API, prisma/schema.prisma, міграції, uploads/
├─ apps/web/        SPA (збирається у apps/web/dist, роздається самим API)
├─ scripts/         backup-crm.ps1
└─ backups/         архіви бекапів (ігнорується git)
```

Продакшн-схема: API роздає `apps/web/dist` через `ServeStaticModule`, префікс API — `/api`, файли — `/uploads/`. Порт — `PORT` або 3000.

## 3. Змінні середовища (`apps/api/.env`)

| Змінна | Призначення |
|---|---|
| `DATABASE_URL` | рядок підключення PostgreSQL (обов'язково) |
| `JWT_SECRET` | секрет підпису токенів (обов'язково, `getOrThrow`) |
| `PORT` | порт API (за замовчуванням 3000) |
| `UPLOADS_DIR` | необов'язково, коренева тека завантажень |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_FULL_NAME` | лише для `seed:admin` (пароль ≥ 12 символів) |

Фронтенд: `VITE_API_URL` (необов'язково; у dev — `http://localhost:3000/api`, у prod — `/api`).

## 4. Модель даних

- **Project** — назва, статус, джерело, бригада, 2 відповідальних, локація, нотатки.
- **ProjectContact** — ПІБ, телефон, роль (OWNER/ACCOUNTANT/ELECTRICIAN/MANAGER/OTHER), посада, `isPrimary`.
- **FinancialTransaction** — INCOME/EXPENSE, сума Decimal(12,2), контрагент, спосіб оплати, рахунок, дата, коментар.
- **TransactionAttachment** — INVOICE / EXPENSE_DOC, файл.
- **ProjectFile** — категорія (PROPOSAL, PROJECT_DOCUMENT, FINANCIAL_DOCUMENT, OTHER), `isFinal` для КП.
- **ProjectMedia** — PHOTO / VIDEO.
- **ProjectTask** — статус TODO/IN_PROGRESS/DONE/CANCELED, пріоритет, `dueDate`.
- **ProjectEquipment** — ORDERED → PAID → IN_STOCK → ON_SITE.
- **User** — email, passwordHash, роль ADMIN/WORKER/VIEWER, `isActive`.

Усі дочірні таблиці мають `onDelete: Cascade` від Project.

### Воронка статусів проєкту (14)

`NEW → PREPARING_PROPOSAL → PROPOSAL_SENT → CONTRACT_APPROVAL → CONTRACT_SIGNED → AWAITING_PAYMENT → PAID → PREPARING_IMPLEMENTATION → IN_PROGRESS → COMPLETED`
Побічні: `PAUSED`, `REFUSED`, `REMIND_LATER`, `NO_LONGER_RELEVANT`.
Статуси змінюються вручну; автоматичних переходів немає.

## 5. Ролі та доступ

Перевіряється глобальним `JwtAuthGuard` лише за HTTP-методом:

| Роль | GET | POST | PATCH/DELETE |
|---|---|---|---|
| ADMIN | так | так | так |
| WORKER | так | так | **ні** |
| VIEWER | так | ні | ні |

Публічні маршрути: `POST /api/auth/login`, `GET /api/health`. Токен живе 8 годин, передається `Authorization: Bearer`, у вебі зберігається в `localStorage`.

### 6.2 Проєкти

### 6.4 Фінанси
- ✅ Сума > 0, до 2 знаків після коми, `Decimal(12,2)`.
- ✅ Вкладення типізовані (INVOICE / EXPENSE_DOC), є ліміт 15 МБ, очистка файлу при помилці запису в БД.
- ✅ Кирилиця в іменах файлів виправляється (mojibake latin1/win1251).

- ⚠️ `UpdateTransactionDto` дозволяє змінити суму/тип без журналу змін (аудит-лог відсутній) — для фінансів це ризик.
- ⚠️ `receiptPath` у моделі — застаріле поле, ніде не використовується (лише в бекап-CSV).
- ⚠️ Дашборд рахує доходи/витрати по **всіх** проєктах, включно з відмовами.

### 6.5 Документи та КП
- ✅ КП має бути PDF; тільки одна «фінальна» КП на проєкт (перемикання у транзакції).
- ❌ **Розходження каталогу завантажень.** `files.controller` пише в жорстко заданий `cwd/uploads/documents`, а `files.service.remove` видаляє з `UPLOADS_DIR || cwd/uploads`. Так само `main.ts` (static) і `projects.remove` ігнорують `UPLOADS_DIR`. Якщо `UPLOADS_DIR` задано — документи не видаляються з диска, а фото/фінансові файли віддаються не звідти. Зараз працює лише тому, що змінна не задана.
- ❌ **Безпека типів файлів.** Умова — «MIME дозволений **АБО** розширення дозволене», обидва значення надає клієнт. Файл `x.html` з MIME `application/pdf` проходить, зберігається з розширенням `.html`. Для медіа ще й приймається будь-який `image/*` (включно з `image/svg+xml`).
- ❌ **`/uploads/` віддається без автентифікації** (`useStaticAssets` обходить guard). Фінансові документи, договори й фото доступні кожному, хто знає URL. Імена — UUID, тому вгадати важко, але посилання не відкликається і не потребує логіну.
- Разом (HTML/SVG з того самого origin без авторизації) — це вектор stored-XSS для тих, хто має право завантажувати (WORKER).
